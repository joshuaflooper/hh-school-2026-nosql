### 1. Redis

1. Rate Limiter — это механизм защиты от большого количества запросов к сервису, которые могут быть вызваны различными вредоносными действиями, например, DDoS-атакой, brute force'ом и т.п. Принцип работы прост — пропустить не больше чем заданное количество запросов в заданный промежуток времени.<br><br>
2. Прочитал статью, в ней были описаны различные алгоритмы. Не вдаваясь в их описание, сразу вспомнил про команду `SET ... EX`, про которую говорилось на лекции. Почитал документацию Redis'a, нашёл отдельную команду `EXPIRE` и параметр `NX` для неё, который добавляет время жизни, только если оно не было добавлено до этого. Сразу напросилась идея сделать для запросов счётчик через string, который умирает через `timeWindowsSeconds` секунд после первого запроса в рамках счётчика. Ну и соответственно при каждом запросе проверять, есть ли живой счётчик и не достигнуты ли `maxRequestCount` запросов. Если запрос проходит, то увеличиваем счётчик или создаём новый, если активного счётчика нет — с точки зрения команды `INCR`, найденной в той же документации, это одно и то же.<br>
Короче, получилось фиксированное окно из статьи. Естественно тест на скользящее окно такой алгоритм не проходит, потому что подсчёт количества выполненных запросов никак не привязан ко времени самого запроса и выполняется только внутри фиксированного периода жизни счётчика.<br>
То есть надо проверять количество запросов, произошедших в течение `timeWindowsSeconds` до запроса. Чтобы проверить, не равно ли оно `maxRequestCount` и можем ли мы воткнуть ещё один запрос, достаточно проверить что запрос номер `maxRequestCount` с конца был выполнен больше, чем `timeWindowsSeconds` секунд назад. Для этого отлично подойдёт list, в который мы будем записывать время выполнения запросов. При каждом запросе выполняем описанную проверку и, если запрос проходит, добавляем текущее время в список. <br>
В итоге получаем скользящий журнал из статьи (ну по-моему). Все тесты проходятся успешно.<br><br>
